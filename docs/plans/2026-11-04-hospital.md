# The Circadian Hospital Implementation Plan
> **For agentic workers:** Execute with superpowers:executing-plans. Owner explicitly asked to start; continue inline through verification without another process approval.

**Goal:** Deliver a polished, search-ready hospital website and genuine enquiry backend, with Sites review publication and Hostinger deployment files.
**Architecture:** Astro pre-renders public routes. Django handles same-origin enquiry API and staff admin, backed by PostgreSQL in production. Sites review mode uses WhatsApp rather than claiming an unavailable Python backend.
**Tech Stack:** Astro, TypeScript, custom CSS, Django, PostgreSQL, Nginx, Docker Compose.
**Spec:** docs/superpowers/specs/2026-11-04-hospital-design.md

## Global constraints
- Phone +918512040000; actual operational status; 250 beds supplied by owner.
- No invented clinical availability, credentials, testimonials, ratings or disease-cure claims.
- Support mobile, keyboard, reduced motion, light/dark preferences and source-backed education.
- Preview is noindex; final canonicals target https://thecircadianhospital.com.
- Secrets/runtime records are ignored. No health-record upload.

## Review focus
- Duplicate submissions cannot duplicate enquiries; reuse with changed details is rejected.
- Invalid/missing consent/mobile, oversized payloads, malformed JSON and CSRF failures do not save.
- Missing backend never displays false success; WhatsApp fallback is explicit.
- Navigation/theme work at narrow widths and with storage blocked; core links work without JS.
- Preview crawl policy cannot accidentally be copied as production indexing configuration.
